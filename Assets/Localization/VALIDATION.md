### 기본 관리 규칙

번역 본문을 높이 0.275의 고정 영역 세 개에 각각 자동 맞춤하면서 글자가 축소됐습니다. 이제 전체 본문 공간을 사용해 세 항목에 같은 크기를 적용합니다. 제목은 뒤로가기 화살표와 분리하고, 붉은 안내와 코드 숫자도 각각의 영역에 표시합니다.

| 언어 | 세 본문의 동일한 실제 크기 | 프로토콜 안내 크기 |
|---|---:|---:|
| 영어 | 0.03243 | 0.04200 |
| 일본어 | 0.02871 | 0.04200 |
| 중국어 간체 | 0.03296 | 0.06000 |
| 중국어 번체 | 0.03296 | 0.06000 |

### 1일차 종료 검은 화면

06:00에서 하루 종료 Timeline과 보고서 표시 콜백은 실행됐지만, 보고서 Canvas의 정렬 순서는 0이고 검은 FadePanel은 1000이었습니다. Timeline이 검은 페이드를 유지하면서 보고서를 가렸습니다. 보고서를 표시할 때 정렬 순서를 1001로 올리고, 확인 후 다음 날 Timeline을 재생하기 전에 원래 순서로 복구했습니다. 중복 확인 요청도 차단했습니다.

같은 보고서 상태에서 원래 정렬 순서로 캡처하면 화면 전체가 검고, 수정된 순서로 캡처하면 보고서가 표시되는 것을 확인했습니다. 비교 이미지는 `.utmp/localization/day1-report-baseline.png`, `day1-report-fixed.png`에 있습니다. 실제 UI 클릭 경로로 1일차→2일차, 2일차→3일차 이동을 확인했으며, 다음 날 시간이 씬에 설정된 시작 시간 00:00으로 초기화되고 다시 근무 종료할 수 있는 상태인 것도 검사했습니다. 3~5일차 전체 플레이는 이번 검사 범위에 포함되지 않습니다.

### Editor 런타임 테스트

**Tools → Testing → Runtime Test** 창의 UI 콜백으로 01:23 설정, 시간·자동 발생 정지, 06:00 이동을 검사했습니다. 게임 씬에 등록된 이상현상 11종을 선택해 실행하고 실제 일반·특수 관리 목록 등록과 중복 실행 거부, 해결 버튼의 정리를 확인했습니다. 새 창은 `Assembly-CSharp-Editor`에서 컴파일됩니다.

Windows x64 Development 빌드는 성공했고, 결과 크기는 1,303,408,246바이트이며 경고 6개였습니다. 실제 Player의 `Assembly-CSharp.dll`을 Mono.Cecil로 검사해 테스트 창 타입 0개, `DaySystem`·`AnomalySystem`의 Editor 테스트 메서드 0개, UnityEditor 참조 0개를 확인했습니다. 배포 DLL에 `ManualRulesLocalizationLayout`은 포함되어 있습니다. 결과는 `.utmp/localization/player-editor-exclusion.json`, 빌드 로그는 `manual-day-runtime-build.log`, Play Mode 결과는 `manual-day-runtime-playmode-result.txt`에 있습니다.

열려 있던 Editor에서 Pipeline을 통해 호출한 빌드는 메인 스레드 응답 제한에 걸려 완료되지 않았습니다. 저장된 씬 상태를 확인한 뒤 Editor를 종료하고, Unity 배치 실행으로 위 빌드 검사를 완료했습니다. 이후 동일한 프로젝트와 Unity 버전의 Editor를 다시 열었습니다. 위 날짜 이동 검사는 Editor Play Mode에서 수행했으며, 빌드 파일을 직접 실행해 게임 전체를 플레이한 검사는 아닙니다.

복구 후 타이틀 씬의 Edit Mode에서 테스트 창을 열어 실행 컨트롤이 비활성화되는 것을 확인했습니다. 마지막 컴파일 실패 및 Console 오류는 0개였고, Console 경고는 1개였습니다.
